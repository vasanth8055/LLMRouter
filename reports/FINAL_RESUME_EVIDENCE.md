## (c) Resume Bullet Sets (Max 2 Lines Each, Non-Inferiority Wording Only)

### Set 1 — ML Systems & Cost-Aware Routing Focus
- Engineered a cost-aware multi-LLM router (**FastAPI**, **scikit-learn**, **PostgreSQL**) that scores `P(correct | prompt, model)` across DeepSeek V3 and Gemini 2.5 Flash/Pro and cuts benchmark inference cost by **23.67%** at **98.68%** of Always-Pro accuracy (`84.53%` vs `85.67%`, non-inferiority lower bound `-1.70 pp > -2.00 pp`, `N = 3,000` 5-fold nested CV).
- Applied inner-validation **Platt scaling** to reduce Pro fallback from **50.77%** to **44.57%** (`-6.20 pp`, 95% paired bootstrap CI `[-7.80, -4.57] pp`) while keeping routing decision latency at **4.65 ms `p95`** vs **28.44 ms `p95`** (`5.94 s` cached cold start) measured with `all-MiniLM-L6-v2` embeddings.
- Diagnosed cross-domain transfer limits across **4,253** prompts (**MMLU-Pro**, **GPQA**, **LiveCodeBench**), showing why out-of-domain code prompts fall back **96.21%–100%** to Pro (`DeepSeek > Flash` rank reversal) and how in-domain calibration recovers **10.59%** coding savings.

### Set 2 — Backend Reliability & LLMOps Infrastructure Focus
- Built an async **FastAPI** routing gateway supporting versioned runtime artifacts (`V2.1 tau=0.90`, `V5 Platt tau=0.85`), artifact-enforced quality floors (`422` validation), exponential backoff + jitter retries (`429`/`5xx`/timeouts), a **120 s** per-request deadline, and cost-ordered provider failover verified via `httpx.MockTransport`.
- Implemented privacy-preserving **PostgreSQL/asyncpg** telemetry (`SHA-256` prompt hashes only, zero raw prompts/responses persisted) with idempotent schema migrations, cost/fallback analytics endpoints, and a **React/TypeScript** monitoring dashboard (**133 passing / 3 external-data skipped pytest** + **10 vitest**).
- Benchmarked and tuned routing inference pipelines using leakage-free 5-fold `GroupKFold` nested CV (**23.67%** cost savings, **98.68%** Pro retention, `p95 = 4.65 ms` routing overhead, **201.3 req/s** in-process ASGI mock throughput).

### Set 3 — Applied ML Evaluation & Systems Rigor Focus
- Eliminated a 70% in-sample leakage flaw via strict 5-fold prompt-grouped nested CV (`N = 3,000` MMLU-Pro) and evaluated **6** routing candidates under pre-registered quality-retention (`>= 98%`), non-inferiority (`-2.00 pp`), and routing-latency (`p95 <= 25 ms`) gates.
- Selected a Platt-calibrated TF-IDF + Logistic Regression router (`84.53%` accuracy, **23.67%** cost savings, **44.57%** fallback, **4.65 ms `p95`**) after rejecting `all-MiniLM-L6-v2` embeddings (`28.44 ms` `p95`, `65.10%` fallback) and subject/metadata models (`97.86%` retention failure).
- Engineered resilient async provider adapters (**DeepSeek** / **Gemini** REST), retry/failover telemetry migrations, and resumable non-test probe tooling; documented cross-domain failure modes across `4,253` benchmark prompts and verified **136** collected backend (**133** passed, **3** skipped without local GPQA/LCB CSVs) + **10** frontend tests.

## (d) 6 Likely Interview Questions & Honest Answers

1. **Q: Did your router actually beat Always-Gemini-Pro?**  
   **A:** No — Always-Pro gets `85.67%` on MMLU-Pro `test_3000` while `5a-platt` gets `84.53%` (`McNemar p = 0.000121`), and on the older 450-prompt split V2.1 (`83.78%` vs `83.33%`) had `McNemar p = 0.6875` (pure parity). The goal is **cost reduction with bounded quality loss (non-inferiority)**: keeping `>= 98%` of Always-Pro accuracy (`98.68%`, 95% CI diff lower bound `-1.70 pp > -2.00 pp`) while saving `23.67%` of inference cost.

2. **Q: Why did Platt scaling cut fallback by `6.20 pp` if ECE was already `0.0177` and Brier stayed flat (`0.1461 -> 0.1463`)?**  
   **A:** Because in our discrete `0.05`-step threshold sweep (`[0.50..0.95]`), uncalibrated `Refit V2.1` selected `tau* = 0.90` on 3 of 5 outer folds (`50.77%` fallback), whereas per-model Platt scaling shifted logit slopes/intercepts enough for 4 of 5 folds to satisfy `>= 98%` Pro retention at `tau* = 0.85`, cutting fallback to `44.57%` (`+2.08 pp` savings). Notice that at a fixed `tau = 0.90`, Platt actually did *worse* (`6.84%` savings vs `9.83%`), proving the improvement is threshold/boundary behavior rather than better probability calibration, and selecting 1 winner out of 6 variants on the same folds carries a selection effect.

3. **Q: Why didn't you ship neural embeddings (`all-MiniLM-L6-v2`) or a gradient-boosted tree?**  
   **A:** We benchmarked `all-MiniLM-L6-v2` empirically in Attempt 5b before building GBT on top. On CPU, single-prompt MiniLM inference had `p95 = 28.44 ms` (`29.37 ms` with TF-IDF), already violating our `25 ms` `p95` routing gate (plus `5.94 s` cached subprocess cold start), *and* it degraded routing economics (`14.76%` savings, `65.10%` fallback vs `23.67%` savings, `44.57%` fallback for `5a-platt`).

4. **Q: What happened when you tested V2.1 / cross-domain routing on LiveCodeBench and GPQA?**  
   **A:** Out-of-domain transfer failed. On LiveCodeBench (`N = 1,055`), `DeepSeek` outperforms `Flash` (`66.64%` vs `60.00%`, opposite MMLU-Pro's `78.00%` vs `80.93%`), and even Always-Pro tops out at `79.15%`, so a `0.90` quality floor causes `96.2%–100%` Pro routing (`0%` savings). On GPQA (`N = 198`, wide CIs), LODO Text-Only dropped accuracy to `81.31%` vs `84.85%` Pro (`-7.58 pp` NI LB). Only when trained/calibrated in-domain on coding prompts (`Single-Domain LCB Nested CV`) did the router shift `15.5%` to DeepSeek (`0%` Flash) and achieve `10.59%` savings (`99.16%` retention).

5. **Q: Why did you audit and throw out the original 5-fold CV and stop using the 450 test split?**  
   **A:** Two separate issues: (1) The 450-prompt held-out test set had already been evaluated across V2, V2.1, V2.2 frontier, and misroute analysis, burning its statistical independence; (2) the earlier Phase 5 CV evaluated static `router_v21_tfidf.joblib` across all 3,000 prompts, meaning 70% (`2,100`) were in its training set! Re-running strict outer-fold refits in Phase 1 lowered apparent retention (`99.96% -> 98.44%`) and revealed true out-of-sample `Refit V2.1` behavior (`21.59%` savings, `50.77%` fallback).

6. **Q: How is the runtime API protected against provider outages, timeouts, and cost/config mismatches?**  
   **A:** Every HTTP provider adapter retries strictly transient errors (`429`, `5xx`, timeouts; never non-429 `4xx`) with exponential backoff + jitter (`max_retries=2`), bounded by an overall `120 s` per-request deadline across retries and cost-ordered failover to `gemini-2.5-pro`. Telemetry persists `attempted_models`, `failover`, `policy_fallback`, and `retry_count` alongside `SHA-256` prompt hashes. Crucially, live API runs remain **`BLOCKED (no API keys in .env)`**, so retries/failover are verified with `httpx.MockTransport` and `/v1/routing/config` keeps canonical benchmark models distinct from live API model IDs.
